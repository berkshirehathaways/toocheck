# [#5] 랜딩 + 서비스 원칙 페이지

## 목적
서비스 진입점과 비당파성 원칙을 명시한다.
**5초 안에 의도를 전달**(랜딩) + **운영 원칙을 외부에서 검증 가능**(원칙 페이지)이 목표.

> 참조: PRD §1, §3, §6.1, §16.1, §19

## 산출물

```
app/(public)/
├── page.tsx                   # 랜딩 (= app/page.tsx에서 이동)
└── principles/
    └── page.tsx

components/domain/
└── PrincipleSection.tsx
```

## 랜딩 (`app/(public)/page.tsx`)

구성:

1. **헤더**: 서비스명 + `/principles` 링크 + (선택) 정정 요청
2. **히어로**
   - 헤드라인: **"공약만 보고 넘기기 전에, 공개자료도 확인하세요."**
   - 서브: "우리 지역 후보의 재산, 납세, 체납, 병역, 전과, 공약을 한 화면에서 비교합니다."
3. **CTA 3개**
   - `내 지역 후보 확인하기` → `/districts` (mock 단계엔 토스트 "현재 테스트 지역만 지원" + 테스트 지역으로 폴백)
   - `테스트 지역으로 보기` → `/districts/${SEED_DISTRICT_ID}/candidates`
   - `서비스 원칙 보기` → `/principles`
4. **미니 설명 카드 3개** (PRD §1 핵심 문장 기반)
   - "공약은 누구나 좋게 씁니다."
   - "공개된 기록도 함께 보세요."
   - "원문 자료가 우선입니다."
5. **푸터**
   - 자료 기준일
   - 정정 요청 안내 + 링크
   - 운영주체 표기
   - 면책 문구 한 줄

## 서비스 원칙 (`/principles`)

PRD §3 전체 + §17 금지어/대체표현 + §19 개인정보 정책 요약.

구성:
1. 서비스 소개 (한 문단, PRD §1 발췌)
2. 5개 원칙 (PRD §3.1~§3.5)
   - 각 원칙: 제목 + 1~2문장 요약 + (접힘) 자세히
3. 금지/허용 표현 표 (PRD §17)
4. 개인정보·로그 정책 (§19 요약)
5. 정정 요청 진입 + 운영주체 표기
6. 문서 버전 + 최종 수정일 (예: `v0.1 · 2026-05-27`)
